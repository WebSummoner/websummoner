WebSummoner is a fast Selenium hub, written in Go, that summons a fleet of
browsers into Docker containers as ephemeral, session-scoped environments. It
reads a small JSON file describing which browser images to launch, starts a
container for each session, and proxies the WebDriver protocol to it.

**Why people use it:**

- **Lightweight** — a single ~10 MB static binary, no Java, roughly 10× less
  memory than a Selenium server under the same load.
- **Fully containerized browsers** — every session gets an isolated,
  reproducible environment with an exact browser version.
- **Built for testing workflows** — video recording with sound, per-session
  logs, live screen viewing (VNC), clipboard and file exchange, DevTools
  protocol access.
- **Observability built in** — a `/status` endpoint and Prometheus metrics
  at `/metrics` covering sessions, queue depth and per-browser usage.
- **Selenium-compatible** — point your existing tests at
  `http://localhost:4444/wd/hub` and they just work.

WebSummoner is developed and maintained by
[RIADVICE](https://riadvice.com) — a Selenium hub updated for current Go
toolchains and modern browser images.

## The 30-second tour

1. Start WebSummoner (Docker path):

   ```bash
   docker run -d --name websummoner -p 4444:4444 \
       -v $PWD/browsers.json:/etc/websummoner/browsers.json:ro \
       -v /var/run/docker.sock:/var/run/docker.sock \
       websummoner/websummoner:latest
   ```

2. Point your tests at `http://localhost:4444/wd/hub`.
3. Open [http://localhost:4444/status](http://localhost:4444/status) to see it working.
